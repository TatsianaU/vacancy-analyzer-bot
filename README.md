# Telegram-бот для анализа вакансий

Учебный бот принимает полный текст вакансии или заказа, который пользователь сам вставляет в Telegram, и разбирает его через OpenAI API. Бот не ходит на сайты, не использует базу данных и не подключает внешние сервисы, кроме Telegram и OpenAI.

## 1. Назначение

Пользователь отправляет текст объявления. Модель разбирает его простым языком для начинающего AI Product Builder: что предстоит сделать и можно ли браться за заказ.

Сначала идут десять пунктов:

1. Краткая суть объявления.
2. Задачи, прямо названные в тексте.
3. Функции специалиста. Если отдельного списка нет, бот выводит их из задач и помечает словами «Предположение:».
4. Необходимые знания: сначала указанные в тексте, затем предполагаемые. Для каждого предположения написано, для какой функции оно нужно.
5. Инструменты, технологии, программы, языки и библиотеки. Если стек не назван, бот предлагает вероятный набор. У каждой предполагаемой технологии есть пометка «Предположение:» и часть задачи, для которой она нужна.
6. Требования, прямо указанные в объявлении.
7. Требования, которые модель только предполагает.
8. Этапы реализации по функциям из пункта 3. Если заказчик этапы не задал, это предложенный план: действие, зависимость от предыдущего шага и готовый результат. Сроков в плане нет.
9. Что в объявлении непонятно или не указано.
10. Вопросы заказчику.

После них идёт отдельный блок «Оценка заказа»: риски, скрытая сложность, реалистичность бюджета и короткий вывод, какие части заказа начинающий может сделать сам.

Бот разделяет три вида сведений:

- прямо написано в объявлении;
- обоснованное предположение: оно начинается со слов «Предположение:» и опирается на формулировку текста;
- нужно уточнить у заказчика.

Версии программ, сроки, инфраструктуру, интеграции и свою цену бот добавляет только тогда, когда они есть в тексте. Правила разбора записаны в системном промпте в `api_client.py`.

## 2. Возможности

- Команды `/start`, `/help` и `/reset`.
- Разбор обычного текстового сообщения по десяти пунктам и блоку «Оценка заказа».
- Вероятный стек и конкретные этапы, если объявление их не называет. Каждое такое утверждение помечено как предположение.
- Уточняющие вопросы по той же вакансии с опорой на предыдущие реплики.
- Короткое сообщение о том, что запрос ещё обрабатывается.
- Отказ, если сообщение длиннее 12000 символов.
- Деление длинного ответа на несколько сообщений Telegram.
- Понятные сообщения об ошибках без ключей, токенов доступа и текста ответа API.
- Журнал в консоли: пользователь, модель, параметры, размер контекста, токены и тип ошибки.

## 4. Установка зависимостей

Нужен Python 3.10 или новее. В `requirements.txt` зафиксированы версии, с которыми проверен проект: `aiogram` 3.31.0, `openai` 3.36.1 и `python-dotenv` 1.2.4. Команды ниже выполняются в PowerShell из папки `vacancy-analyzer-bot`.

```powershell
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

Если активация сценария запрещена политикой PowerShell, для текущего окна достаточно такой команды:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
```

После этого снова выполните `.\.venv\Scripts\Activate.ps1`. Запускать бота можно и без активации:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe bot.py
```

## 5. Виртуальное окружение в Windows PowerShell

Отдельное окружение лежит в папке `.venv` внутри проекта. Его не нужно копировать на другой компьютер и нельзя публиковать: пакеты устанавливаются заново командами из раздела 4.

Проверка, что используется интерпретатор из окружения:

```powershell
python -c "import sys; print(sys.prefix)"
```

В пути должен быть каталог `.venv`.

## 6. Настройка .env

```powershell
Copy-Item .env.example .env
```

Откройте `.env` и заполните его. Пример состава файла:

```env
BOT_TOKEN=
OPENAI_API_KEY=
OPENAI_MODEL=
TEMPERATURE=0.3
MAX_TOKENS=1200
```

| Переменная | Обязательна | Значение |
|---|---|---|
| `BOT_TOKEN` | да | токен бота от [@BotFather](https://t.me/BotFather) |
| `OPENAI_API_KEY` | да | ключ OpenAI API |
| `OPENAI_MODEL` | нет | пустое значение включает модель по умолчанию `gpt-4o-mini` |
| `TEMPERATURE` | нет | по умолчанию `0.3`, допустимо от 0 до 2 |
| `MAX_TOKENS` | нет | по умолчанию `1200`. Полный разбор с оценкой заказа может оказаться длиннее; если ответ обрезан, бот пишет об этом в конце сообщения |

Имя модели задаётся в коде только в `config.py` и читается из `OPENAI_MODEL`. Если переменная пустая, используется `gpt-4o-mini`: недорогая текстовая модель без скрытого шага рассуждения. Она поддерживает Chat Completions и параметр `temperature`, поэтому подходит для сравнения ответов при 0.2, 0.6 и 0.9.

`MAX_TOKENS` из `.env` передаётся в API как `max_completion_tokens`. В установленной библиотеке `openai` это актуальное имя лимита ответа; старый вызов `openai.ChatCompletion.create` не используется.

Настройки и системный промпт читаются при запуске. После изменения `.env` или `api_client.py` бота нужно остановить и запустить снова.

Без `BOT_TOKEN` или `OPENAI_API_KEY` процесс завершается с кодом 1 и пишет, каких переменных не хватает. Сами значения в ошибку не попадают.

## 7. Запуск

```powershell
.\.venv\Scripts\Activate.ps1
python bot.py
```

Остановка: `Ctrl+C`.

В консоли при старте будет строка с моделью, `temperature` и `max_tokens`. После каждого запроса к модели появляется статистика токенов. Текст объявления и ключи туда не пишутся.

## 8. Команды

| Команда | Действие |
|---|---|
| `/start` | объясняет, зачем бот, и просит прислать объявление |
| `/help` | показывает порядок работы |
| `/reset` | удаляет контекст текущего пользователя |

Дальше пользователь отправляет текст объявления. Следующие обычные сообщения считаются вопросами по этому разбору, пока не выполнена команда `/reset`.

## 9. Хранение контекста

Контекст хранится в обычном словаре `dict` в оперативной памяти. У каждого `user_id` своя история. В ней лежат только реплики пользователя и ответы ассистента, не больше 12 последних сообщений. Системный промпт в историю не записывается: он добавляется отдельно на время запроса.

`/reset` очищает историю только этого пользователя. Перезапуск бота удаляет контекст всех диалогов, потому что словарь не сохраняется на диск.

В журнал поле `context_messages` пишет, сколько реплик диалога ушло в запрос вместе с новым сообщением пользователя. Системный промпт в это число не входит.

## 10. Безопасность ключей

- Настоящие `BOT_TOKEN` и `OPENAI_API_KEY` записывайте только в локальный `.env`.
- `.env.example` оставляйте с пустыми секретами.
- `.gitignore` исключает `.env`, оба каталога виртуального окружения и кэш Python.
- Не отправляйте ключи в чат, на скриншоты и в журнал.
- В логах нет значений `BOT_TOKEN` и `OPENAI_API_KEY`. Для ошибок сохраняется только тип исключения, без текста ответа API.
- Журналы `openai`, `httpx`, `httpcore`, `httpx2` и `httpcore2` ограничены уровнем WARNING. Подробный журнал этих библиотек может содержать адрес запроса.
- Если ключ уже попал посторонним, удалите его в BotFather или в кабинете OpenAI и создайте новый.

Git-репозиторий для этого проекта пока не создаётся.

## 12. Таблица экспериментов

Для трёх прогонов используйте одну и ту же вакансию. Перед каждым прогоном меняйте `TEMPERATURE` и `MAX_TOKENS`, перезапускайте бота и отправляйте `/reset`. Числа токенов копируйте из консоли. Стоимость посчитайте по актуальному прайсу OpenAI:

```text
стоимость = input_tokens / 1000000 * цена_входа + output_tokens / 1000000 * цена_выхода
```

Для модели по умолчанию `gpt-4o-mini` в прайсе OpenAI на октябрь 2026 указано $0.15 за 1 млн входных токенов и $0.60 за 1 млн выходных. Перед расчётом сверьте цены на странице OpenAI: они могли измениться.

Прогон 1 записан по консоли от 22 октября 2026: разбор вакансии после `/reset` при `context_messages=1`. Уточняющие вопросы того же диалога в эту строку не входят. Прогоны 2 и 3 пока пустые.

| Модель | Temperature | Max tokens | № прогона | Тестовый запрос | Получившийся эффект | Input tokens | Output tokens | Total tokens | Ориентировочная стоимость |
|---|---:|---:|---:|---|---|---:|---:|---:|---:|
| `gpt-4o-mini` | 0.2 | 3000 | 1 | Одна и та же тестовая вакансия | Стабильный структурированный ответ, контекст работает; некоторые технические выводы потребовали уточнения | 1435 | 763 | 2198 | $0.00067 |
|  | 0.6 | 1000 | 2 | Та же вакансия |  |  |  |  |  |
|  | 0.9 | 1200 | 3 | Та же вакансия |  |  |  |  |  |

Стоимость прогона 1 посчитана по формуле выше и ценам `gpt-4o-mini` из этого раздела: 1435 / 1000000 × $0.15 + 763 / 1000000 × $0.60.
